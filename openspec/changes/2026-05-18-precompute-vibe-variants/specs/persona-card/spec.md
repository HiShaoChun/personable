## ADDED Requirements

### Requirement: 后台预生成 vibe 变体
首次人格卡定稿后，前端 SHALL 在后台立即并发预生成其余支持的 vibe
变体；用户点击「换个风格」时，命中预生成结果者 SHALL 瞬时替换卡片，
未命中者退化到现有的按需重合成路径。预生成 SHALL 完全静默——既不
向用户呈现进度或失败，也不阻塞主流程。

#### Scenario: 首次定稿后启动预生成
- **WHEN** 一次 agent 运行成功完成且人格卡已渲染
- **THEN** 系统把当前 vibe 的成品（含分享 ID 与画像）放入客户端缓存
- **AND** 对其余每个支持的 vibe，并发对重合成端点发起一次后台请求
- **AND** 预生成请求与用户点击触发的重合成在服务端走完全相同的路径
  与安全闸门（限流、并发槽、每日预算、token 预算），不引入旁路或
  特权参数

#### Scenario: 点击命中预生成缓存
- **WHEN** 用户在终态点击某个 vibe 按钮且该 vibe 已存在预生成结果
- **THEN** 系统同步替换人格卡为该 vibe 的预生成成品，分享链接 ID
  同步切换为对应 vibe 的独立 ID
- **AND** 按钮不进入「生成中…」状态，不发起任何新的网络请求

#### Scenario: 点击未命中预生成缓存
- **WHEN** 用户在终态点击某个 vibe 按钮且该 vibe 尚无预生成结果
- **THEN** 系统按当前路径发起一次重合成请求并展示「生成中…」反馈
- **AND** 该请求成功返回后，其结果同样回填到客户端缓存，下一次
  切回同一 vibe 时呈瞬时切换

#### Scenario: 预生成失败静默处理
- **WHEN** 预生成请求因限流、并发槽满、每日预算耗尽、合成失败、
  网络错误或 agent 状态过期而失败
- **THEN** 系统不向用户呈现错误、不写入缓存、不重试
- **AND** 后续用户点击对应 vibe 按钮按未命中场景处理

#### Scenario: 重新上传文件清空预生成缓存
- **WHEN** 用户在终态拖入另一份书签 HTML 文件
- **THEN** 系统在新一次运行开始处清空上一轮的预生成缓存
- **AND** 任何上一轮仍在进行的预生成请求即使后续返回，其结果也不
  会污染新一轮的缓存
