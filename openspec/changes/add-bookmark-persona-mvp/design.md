## Context

全新的病毒式 Web 玩具：拖入 Chrome 书签 HTML 导出文件，得到一张可分享的「互联网
人格卡」。书签导出（Netscape 书签文件格式）已携带强信号——每条都有标题、URL、
域名、文件夹路径和 `ADD_DATE`——所以 v1 无需通用网页爬取。前期已与用户敲定三个
基础决策：

1. **架构**：托管 Next.js 应用 + 服务端 Anthropic Key（不是纯静态自带 Key，也不是
   本地 CLI）。我们承担 token 成本、自己扛滥用面，换取零门槛「立即试用」的传播力。
2. **聚类**：单次 LLM 聚类（喂标题+文件夹路径+域名，由模型分组、命名、推断人格），
   不用 embedding+kmeans。
3. **Agent 深度**：真正的多步服务端 agent——概览扫描 → 一次性聚类 → agent 自主
   决定深挖哪些簇并抓取少量代表性网页 → 画像合成。「它自己决定你身上什么值得研究」
   是传播钩子。

约束：单人开发，MVP 约 1 周，必须可截图分享，必须有站得住的隐私叙事（因为解析后
的数据会经过我们后端）。**部署目标为开发者自有的 ECS 服务器**（自托管 Next.js +
同机存储），非托管 Serverless/KV 平台。

## Goals / Non-Goals

**Goals:**
- 客户端解析书签 HTML；只有最小化的结构化条目离开浏览器，原始文件绝不上传/持久化。
- 一个有界、可观测的多步 agent 产出结构化人格画像（命名簇、人格特质、兴趣演变线）。
- 一张精致的人格卡，支持一键导出图片和分享链接。
- 公开前具备硬性的成本/滥用上限。

**Non-Goals:**
- v1 不做 Chrome 扩展（仅支持导出 HTML 上传；扩展是 v2）。
- v1 不接入浏览历史（仅书签）。
- 不做全量网页爬取；仅抓取少量有界样本网页。
- 不做账号体系，除带 TTL 的分享卡外不持久化任何画像。
- v1 不做多浏览器导入（Firefox/Safari）。

## Decisions

### D1 — 客户端解析，最小化服务端载荷
在浏览器内解析 Netscape 书签 HTML，只把 `{title, url, domain, folderPath[],
addDate}` 数组发往服务端。理由：隐私叙事（「我们从不接收你的文件」）、更小载荷、
校验更便宜。否决备选（服务端解析上传文件）：隐私叙事更弱、攻击面更大。

### D2 — 一次性 LLM 聚类，而非 embedding
把结构化列表（标题+文件夹路径+域名）一次性发给 Claude 聚类，返回带成员索引的命名
簇 + 初版人格草图。理由：最简单、有 agent 味、对玩具够用；文件夹路径是用户自己写
的标签，让 LLM 聚类很强。否决备选（embedding + HDBSCAN/kmeans 再 LLM 命名）：v1
多一层依赖、调参与基建，质量收益边际。

### D3 — Agent 循环 = Claude 工具调用，且有界
agent 在服务端通过 Anthropic SDK 工具调用循环运行，工具集固定且小：
- `get_overview()` → 计数、域名直方图、时间跨度、文件夹树摘要（本地计算，便宜；
  非 LLM 调用）。
- 一次性聚类作为一个结构化模型回合执行（D2）。
- `fetch_page(url)` → 抓取并返回单个 URL 的可读正文（裁剪后）。硬上限：每次运行
  最多 **N=8** 次抓取、单次超时、体积上限、仅文本、SSRF 白名单（仅 http/https 公网
  主机；屏蔽内网/环回/链路本地）。
- `finalize_profile(profile)` → agent 的终止动作；按 schema 校验。
agent 依据概览 + 聚类结果自主决定哪些簇值得 `fetch_page`。循环受这些约束兜底：
最大工具迭代数、最大墙钟时间、最大抓取数、最大总 token。理由：既有真正的多步自主
（传播钩子），又能可证明地限定成本与时延。否决备选（单个超大 prompt）：与产品的
「原生 agent」卖点矛盾。

### D4 — 模型分层控成本
分流/概览推理与聚类用便宜快的模型（`claude-haiku-4-5`）；最终人格合成用
`claude-sonnet-4-6` 保证面向用户文案的质量。无论如何强制 token 上限。理由：被
截图的是合成文案，把钱花在那里，其余省着。全局每日预算（D7 熔断）实现为
**按当天完成运行数计数**，默认 `DAILY_RUN_BUDGET=100`，外加单次运行 token 硬上限
`PER_RUN_MAX_TOKENS`；全部集中在仓库根 `.env.example`，改一行即可、无需改代码、
次日自动恢复。

### D5 — 用抽样设输入上限
处理条目数上限 **约 800** 条。超出时按文件夹/域名/时间分布做确定性分层下采样，
保证人格仍有代表性。理由：为有上千书签的重度用户限定 token 成本与时延。

### D6 — 分享卡 = 带 TTL、随机 ID 为键的画像 JSON
成功后只存合成后的画像 JSON，以随机不可猜 ID（如 nanoid）为键，**TTL 为 7 天**；
卡片页按该 ID 渲染；图片导出在客户端完成（html-to-image / canvas）。不存任何原始
或结构化书签数据——只存派生画像。存储**自托管在开发者的 ECS 机器**（Redis 用原生
键 TTL，或 SQLite 加 `expires_at` 字段 + 定期清扫）——不用托管 KV。链接**仅凭
链接可见**（不可猜 ID，v1 无公开 gallery/发现）。理由：既支撑分享链接（核心传播），
又最小化留存个人数据，且基建在自有硬件上。

### D8 — 「换个风格重新生成」纳入 v1
卡片 UI 提供一个控件，用不同人格*风格*（如 真诚 / 毒舌 / 诗意）重跑合成。风格是
一个固定的服务端参数，只改变语气与侧重，**不重跑有界深挖**；它在已算好的
簇/概览上重新合成，把额外成本控制在约一次合成调用，而非一次完整 agent 运行。每个
风格变体得到自己的分享 ID/链接。理由：多个可截图变体强力助推分享循环；复用此前的
agent 状态把边际成本压住。否决备选（每个风格跑完整 agent）：成本翻倍、质量增益小。

## Risks / Trade-offs

- 病毒峰值导致成本爆炸 → D4 模型分层 + D5 输入上限 + D7 限流 + 全局每日 token 预算
  熔断开关。
- `fetch_page` SSRF / 抓取内网主机 → 严格公网主机白名单，屏蔽 RFC1918/环回/链路
  本地，仅 http(s)，不跟随跳向内网的重定向。
- 网页抓取慢/不可靠（付费墙、纯 JS 站点）→ 抓取为尽力而为；抓取失败时 agent 必须
  仅凭标题/文件夹/域名也能产出完整画像（优雅降级，绝不硬失败）。
- 隐私观感（「你拿了我的浏览数据」）→ D1 客户端解析 + D6 仅存派生数据 + 明确声明；
  对一个分享型玩具来说，这既是技术风险也是叙事风险。
- LLM 聚类不稳定 / 不当或不讨喜的输出 → 受约束的输出 schema、语气/安全 system
  prompt、卡片上固定免责声明。
- 时延伤害分享循环 → 有界循环（D3）+ 渐进式 UI（概览/簇先流式出来，深挖后补完）。

## Migration Plan

全新项目——无迁移。部署为自托管 Next.js，跑在开发者 ECS 上，同机带存储（Redis 或
SQLite）。上线节奏：先接好 env 门控特性开关与全局 token 熔断；以低限流上限软启动；
观察到成本遥测后再抬上限。回滚 = 关闭开关（前端继续在线，agent 路由返回友好的
「已暂停」状态）。

## Resolved Decisions

- 分享卡留存 TTL = **7 天**；链接**仅凭链接可见**（v1 无公开 gallery）。→ D6
- 存储 = **自托管在开发者 ECS**（Redis 或 SQLite），不用托管 KV。→ D6
- 「换个风格重新生成」**纳入 v1**，实现为在缓存 agent 状态上仅重跑合成。→ D8
- 全局每日预算默认 = **每天 100 次完整运行**（`DAILY_RUN_BUDGET=100`），再加
  单次运行 token 硬上限（`PER_RUN_MAX_TOKENS`）作为单次成本天花板。熔断按「当天
  已完成运行数」计数，最贴合心智模型；次日自动恢复。所有限值集中在仓库根
  `.env.example`，改一行即可调整，无需改代码。→ D4/D7
