# Personable（标签人间）— 书签人格卡 MVP

> 拖入浏览器书签 → 得到一张可炫耀、可分享的「互联网人格卡」。

## Why

人们攒下成百上千条浏览器书签，里面悄悄编码了他们的兴趣、执念以及兴趣随时间的迁移
——但没有一个有趣、可炫耀的方式把这面"镜子"展示出来。"拖入书签 → 得到一张互联网
人格卡"这种玩具天然适合截图、能自传播；而书签导出文件本身信息已足够丰富，第一版
无需抓取网页正文。

## What Changes

- 新增一个 Web 应用：用户上传/拖入 Chrome「导出书签」生成的 HTML 文件；文件在
  浏览器内解析为结构化条目（标题、URL、域名、文件夹路径、添加时间），原始文件
  绝不上传、绝不持久化。
- 新增一个托管在服务端的**多步 agent**：先扫描书签概览，再做一次 LLM 聚类，
  然后**自主决定**哪些簇值得深挖，按需抓取少量代表性网页，最终产出结构化人格画像
  （命名的兴趣簇、人格特质、兴趣演变时间线）。
- 新增可分享的人格卡视图：把画像渲染成精致的视觉卡片，支持一键导出图片和分享链接。
- 新增「换个风格重新生成」：在已算好的 agent 结果上，只重跑合成步骤换一种语气画像。
- 新增托管后端的安全护栏：按会话/IP 限流、输入体积上限、滥用处理、Anthropic API
  Key 仅留服务端、明确的数据处理/隐私声明（架构选型为：托管后端 + 我们的 Key）。

## Capabilities

### New Capabilities
- `bookmark-import`: 在浏览器端接收并解析 Chrome 书签 HTML 导出文件，得到经校验、
  去重的结构化条目；强制体积/格式上限；原始文件绝不持久化。
- `persona-agent`: 服务端多步 agent，把结构化书签条目经「概览扫描 → 一次性 LLM
  聚类 → 自主选择性深挖（有界网页抓取）→ 画像合成」转化为结构化人格画像；并支持
  在缓存的 agent 结果上按风格重合成。
- `persona-card`: 把人格画像渲染为可分享视觉卡片，支持图片导出与分享链接，并提供
  「换个风格重新生成」入口。
- `api-safeguards`: 通过限流、输入上限、滥用处理、全局成本熔断和明确的隐私/数据
  处理声明，保护托管后端与服务端 Key。

## Impact

- 新建 Next.js 应用（App Router）：客户端上传/解析 UI、承载 agent 的服务端路由、
  人格卡渲染与导出。**部署目标为开发者自有的 ECS 服务器**（自托管 Next.js +
  同机存储），非托管 Serverless/KV 平台。
- 新增对 Anthropic SDK（Claude）的依赖，用于聚类/合成以及 agent 循环内的有界网页
  抓取；`ANTHROPIC_API_KEY` 仅存于服务端。
- 新增分享链接所需的存储（最小化：以随机 ID 为键的画像 JSON，7 天 TTL；不存原始
  书签数据），自托管在 ECS（Redis 或 SQLite）。
- 成本/滥用面：每次运行消耗模型 token → 公开前必须先有限流、输入上限与全局熔断。
- 隐私面：结构化条目会经过我们后端 → 需明确数据处理声明，并保证原始文件不持久化。
